Что освоишь

Найдёшь источник учебного материала и источник оценки, соберёшь воспроизводимое свидетельство и объяснишь решение о переходе дальше.

Что сдашь

Короткий отчёт о проверке поиска, ответы на пять вопросов и объяснение своими словами. План времени — 24 минуты на модель, 72 на эксперименты и лабораторную, по 12 на проверку и закрепление.

От страницы до проверенного навыка

Цель академии — уметь спроектировать поиск, измерить его качество и разобраться в сбое. Каждый урок заканчивается небольшим инженерным решением, которое коллега сможет проверить.

Published · материал доступен
В GitHub лежат HTML и lesson.json. Генератор добавляет урок в каталог, GitHub Actions проверяет сборку и публикует Dashboard.
Studied · работа представлена
Ты изучил страницу, провёл эксперимент и прислал результаты. На Code Review наставник сверяет их с критериями приёмки. При расхождении возвращает конкретную проверку на исправление.
Verified · знания подтверждены
После ревью наставник записывает оценки, объяснение, evidence и итог в Google Sheets и перечитывает запись. По ней следующий чат находит точку продолжения.
Как выглядит evidence в проекте ASP.NET Core?

Пусть Search API принимает «термос». В отчёте укажи версию приложения, исходный каталог, параметры запроса, ожидаемые ID и фактический ответ. С такой записью коллега сможет повторить проверку после изменения кода. Для расхождения сохрани исходный результат и добавь отдельный повторный запуск после исправления.

Ошибки при сдаче

В отчёте только скриншот выдачи

По картинке трудно восстановить входные данные. Добавь запрос, версию, исходный набор и ID результата.

Ожидание записано после запуска

Так баг легко принять за требование. Сначала сформулируй ожидаемое поведение, затем запиши наблюдение и сравни их.

Средняя оценка выглядит достаточной

Пороги теории и практики проверяются отдельно. После исправления приложи новую попытку и укажи, что изменилось.

Самостоятельная лабораторная

Можно ли принять сборку поиска?

Ты принимаешь поиск каталога для Next.js-витрины. Требование владельца: запрос находит все названия, равные ему без учёта регистра. Порядок ID произвольный. Используй три записи из Playground.

  1. Выбери запрос с совпадениями и запрос без совпадений. Для каждого заранее запиши ожидаемые ID.
  2. Прогони оба запроса на v1 и v2. Для каждого из четырёх запусков сохрани сборку, вход, ожидание, фактические ID и результат сравнения.
  3. Передай коллеге инструкцию повторения с исходными данными. Реши, какую сборку примешь, и подкрепи вывод конкретным запуском.
  4. Укажи, где хранится учебный материал и кто подтверждает результат. Своими словами объясни, что отделяет сдачу отчёта от Verified.

Критерии приёмки · 100 баллов. Данные и шаги воспроизведения — 20, ожидания из требования — 20, четыре точных наблюдения — 30, вывод с доказательством — 20, корректная передача результата на ревью — 10. Для зачёта практики нужно 90.

Knowledge Check

Пришли ответы вместе с отчётом. Каждый вопрос стоит 20 баллов, проходной результат — 80.

  1. Где найдёшь точную версию страницы и где проверишь последнюю подтверждённую компетенцию?
  2. Страница доступна в Dashboard. Что можно заключить об ученике?
  3. Теория 95, практика 89. Какое решение примет ревьюер и почему?
  4. Два разработчика ввели одинаковый запрос и получили разные ID. Какие две детали эксперимента проверишь сначала?
  5. Оценки достигли порогов. Что ещё требуется для перехода к следующему HTML?

Закрепление. Закрой страницу и за минуту объясни коллеге, как воспроизвести спорный результат и где найти решение ревьюера.
