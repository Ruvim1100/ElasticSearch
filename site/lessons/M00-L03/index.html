01
Why It Matters

Почему «нашёл код» не значит «можно запускать»?

Представь, что коллега скопировал запрос из старого блога. На его ноутбуке он работает, а в production — нет. Причина может быть в версии API, версии клиента, правах доступа или типе развёртывания.

Source

Официальный источник

Docs описывает назначение возможностей. API Reference фиксирует HTTP method, path, request и response.

Version

Проверь цифры

Major 9, minor 2, patch 0 — версия 9.2.0. Возможность из 9.4 не обязана быть в 9.2.

Availability

Проверь условия

GA — Generally Available; Beta — предварительная функция. Stack и Serverless могут различаться.

Результат урока: ты сможешь составить «паспорт API» с методом, маршрутом, JSON, версией, ссылкой на документацию, правами и ограничениями. Это уже инженерное доказательство, а не догадка.

Предварительные знания: HTTP, JSON и результаты проверок M00-L01/L02. Ничего устанавливать не нужно.

03
Guided example · Не оценивается

Как определить версию Elasticsearch?

В обычном Elasticsearch Stack можно использовать официальный Get cluster info. На странице API Reference v9 находится операция GET /.

Input · Учебные данные
GET /

{
  "version": {
    "number": "9.2.0"
  }
}

Синтетический JSON. Мы не обращаемся к реальному кластеру.

Expected → Actual → Conclusion

Ожидание: поле version.number содержит версию Stack.

Наблюдение: учебный ответ вернул 9.2.0.

Вывод: проверяем API Reference v9 и пометки доступности конкретной функции. Это ещё не гарантия совместимости любого примера.

Официальный Get cluster info ↗

Важное исключение: Elasticsearch Serverless использует поле version.number из GET / для обратной совместимости. Оно не отражает фактическую версию Serverless. Для Serverless всегда проверяй отдельные сведения о доступности функций.

Почему одной ссылки на v9 недостаточно?

Документация v9 может описывать функцию, которая появилась в более позднем minor-релизе. Смотри Added in, deployment badges, release notes, права и требования к клиенту.

06
Interactive 3 · JSON Inspector

Изучи реальный формат ответа

Загрузи один из синтетических ответов, измени JSON и запусти проверку. Здесь увидишь, почему одно и то же поле может иметь разный смысл для Stack и Serverless.

Действие
Нажми «Разобрать ответ».
Как это выглядит в C# (серверная сторона)?
using System.Net.Http.Json;
using System.Text.Json;

using var response = await httpClient.GetAsync("/");
response.EnsureSuccessStatusCode();
var body = await response.Content.ReadFromJsonAsync<JsonElement>();
var version = body
    .GetProperty("version")
    .GetProperty("number")
    .GetString();
// Для Serverless это поле НЕ означает версию релиза.

В реальном проекте HttpClient должен быть правильно настроен на сервере, с TLS и credentials из защищённого хранилища. Это иллюстрация чтения JSON, а не готовый production-код.

Anti-pattern: взял пример из блога и сразу отправил в production

Автор мог использовать другой API, старую версию или другое окружение. Сначала ищи контракт в официальном Reference, затем пробуй на синтетических данных, включая ошибки и крайние случаи.

Anti-pattern: v9 означает, что любой пример v9 доступен

Нет. Новые возможности могут появляться внутри 9.x. Обязательно проверяй минимальный minor и наличие функции в целевом deployment.

Anti-pattern: Serverless version.number = фактический релиз

В Serverless ответ существует для обратной совместимости. Это не надёжный номер версии продукта, который обновляется автоматически.

Anti-pattern: compatibility mode гарантирует полное совпадение с v8

Не гарантирует. Это помощь при миграции REST API; она не отменяет breaking changes, тестирование и проверку журналов deprecation.

Production scenario · AcademyShop

ASP.NET Core + Elasticsearch Stack 9.2.0

Товары хранятся в PostgreSQL, а Elasticsearch используется для поиска. Разработчик оставил кусок кода из блога:

GET /products/search
{
  "query": {
    "match": { "title": "чай" }
  }
}

Есть индекс products, документ с ID 42 и пакет Elastic.Clients.Elasticsearch ветки 9.x. Настоящий кластер не нужен: изучай документацию, фиксируй доказательства и предлагай безопасный план проверки.

A · Search

Проверь маршрут

Найди официальный v9 Search API: method, path, JSON, ссылку. Сравни с примером из блога и предложи действие.

B · Get by ID

Найди документ

Найди v9 API для получения товара по ID 42. Укажи method, path, отличие от поиска, сценарий отсутствующего ID.

C · Version Gate

Подтверди версию

Расскажи, как убедиться в версии Stack 9.2.0 и почему v9 Reference не подтверждает любую более новую функцию.

D · Handoff

Подготовь Evidence

Собери ссылки, дату, проверенные факты, дальнейшие тесты и рекомендацию. Никаких персональных данных и секретов.
