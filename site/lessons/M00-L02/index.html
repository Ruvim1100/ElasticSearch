02 · Тренировка · HTTP

Как клиент и сервер общаются?

HTTP — протокол обмена данными. Request — запрос клиента (метод, адрес, иногда тело), Response — ответ сервера (статус, заголовки, иногда тело).

Разобранный пример

GET /api/products/1

HTTP/1.1 200 OK
Content-Type: application/json

{"id":1,"title":"Чай"}

GET просит получить товар; 200 означает успех, 404 — ресурс не найден, 400 — некорректный запрос. Ошибку сервера обычно отражают статусы 5xx.

Почему GET и POST — не одно и то же?

GET предназначен для получения представления ресурса и не должен менять состояние сервера; POST передаёт данные на обработку, например для создания ресурса. Поведение задаётся конкретным API.

03 · Тренировка · JSON

Как устроен формат данных?

JSON — текстовый формат. Объекты используют фигурные скобки { }, массивы — квадратные [ ], а имена полей и текстовые строки пишутся в двойных кавычках.

Разобранный пример

{
  "id": 1,
  "title": "Чай",
  "price": 49.5,
  "inStock": true,
  "tags": ["напитки", "чай"]
}

id и price — числа, title — строка, inStock — логическое значение, tags — массив. JSON не допускает одинарных кавычек вокруг строк и лишней запятой после последнего поля.

04 · Тренировка · SQL

Как выбрать данные из таблицы?

SQL — язык работы с реляционными базами. SELECT задаёт нужные поля, FROM — таблицу, WHERE — фильтр, ORDER BY — сортировку.

idtitlepricecategory
1Чай40drinks
2Кофе90drinks
3Книга150books
4Словарь120books

Разобранный пример

SELECT id, title
FROM products
WHERE price >= 90
ORDER BY price DESC;

Выбираем ID и названия товаров с ценой от 90 и сортируем их от большей цены к меньшей. Столбец сортировки не обязательно выводить через SELECT.

05 · Тренировка · Docker

Image, Container и Volume

Docker Image (образ) — шаблон с файлами приложения. Container — экземпляр образа, в котором запускается процесс. Volume — отдельное управляемое хранилище, которое может сохраняться после удаления контейнера.

DockerfileИнструкции сборки
→
ImageШаблон
→
Container + VolumeЗапуск и данные

Разобранный пример

docker run --name demo -p 8080:80 example-app:1

Образ example-app:1 запускают в контейнере demo. Порт 8080 на компьютере направлен в порт 80 контейнера. Здесь ничего запускать не нужно.

Выбери понятие

Важно: контейнер и том не заменяют backup. Открытие порта и запуск без ограничений — не готовая production-конфигурация.

06 · Тренировка · Search

Где находится поиск в архитектуре?

PostgreSQL часто остаётся источником истины для цен и заказов, а Elasticsearch — поисковой проекцией данных. Обновления могут появляться в поиске с задержкой: это один из примеров eventual consistency (итоговая согласованность).

Первый взгляд на REST Elasticsearch 9.x

GET /products/_search
{
  "query": {
    "match": {
      "title": "чай"
    }
  }
}

Запрос ищет по полю title индекса products. Конкретная выдача зависит от mapping, analyzer и параметров Query DSL. Детально изучим это позже.

Почему Elasticsearch может вернуть другой результат?

Его поведение зависит от типа поля (например, text или keyword), анализатора текста и конкретного вида запроса. Дополнительно может влиять релевантность. Наш пример лишь сравнивает строки.

Связь с C# и TypeScript

Оба примера ниже вызывают собственное API магазина, а не Elasticsearch напрямую из браузера. Ключи Elasticsearch нельзя хранить в frontend.
